## Kiến trúc RESTful và DRF nâng cao

Ngoài phương pháp đã học ở bài trước, việc sử dụng DRF để tạo giao diện dữ liệu (API) theo phong cách REST cũng có thể được thực hiện thông qua hình thức CBV (Class-Based View - view dựa trên lớp). Đặc điểm của việc dùng CBV để tạo giao diện dữ liệu là mã nguồn ngắn gọn, hiệu suất phát triển cao, tuy nhiên tính linh hoạt không bằng FBV (Function-Based View - view dựa trên hàm), bởi vì với phương thức FBV, mã lệnh thực thi và dữ liệu trả về của view function tương ứng có thể tùy biến ở mức độ rất cao. Dưới đây chúng ta sẽ lấy ví dụ về việc tùy biến API dữ liệu môn học để giải thích cách làm cụ thể thông qua CBV.

### Sử dụng CBV

#### Kế thừa lớp con của APIView

Chỉnh sửa tệp `polls/views.py` trong dự án trước đó, bỏ view function `show_subjects`, thêm một lớp có tên là `SubjectView` kế thừa từ `ListAPIView`. `ListAPIView` có thể tiếp nhận yêu cầu GET, nó đóng gói sẵn phương thức `get` để lấy danh sách dữ liệu và trả về dữ liệu JSON. `ListAPIView` là một lớp con của `APIView`, ngoài ra `APIView` còn có rất nhiều lớp con khác, chẳng hạn như `CreateAPIView` hỗ trợ yêu cầu POST, `UpdateAPIView` hỗ trợ yêu cầu PUT và PATCH, `DestroyAPIView` hỗ trợ yêu cầu DELETE. Đoạn mã của `SubjectView` như sau:

```Python
from rest_framework.generics import ListAPIView


class SubjectView(ListAPIView):
    # Chỉ định cách lấy dữ liệu môn học qua queryset
    queryset = Subject.objects.all()
    # Chỉ định cách tuần tự hóa dữ liệu môn học qua serializer_class
    serializer_class = SubjectSerializer
```

Như vừa đề cập, do lớp cha `ListAPIView` của `SubjectView` đã triển khai sẵn phương thức `get` để xử lý yêu cầu GET lấy danh sách môn học, nên chúng ta chỉ cần khai báo cách lấy dữ liệu môn học và cách tuần tự hóa dữ liệu môn học: phần trước được chỉ định qua thuộc tính `queryset`, phần sau được chỉ định qua thuộc tính `serializer_class`. Để sử dụng `SubjectView` ở trên, cần chỉnh sửa tệp `urls.py` như sau:

```Python
urlpatterns = [
    path('api/subjects/', SubjectView.as_view()),   
]
```

Rõ ràng, cách làm trên đơn giản hơn nhiều so với FBV đã đề cập trước đó.

#### Kế thừa ModelViewSet

Nếu API dữ liệu môn học cần hỗ trợ các yêu cầu GET, POST, PUT, PATCH, DELETE để phục vụ các thao tác lấy, thêm mới, cập nhật, xóa tài nguyên môn học, thì cách đơn giản hơn là kế thừa `ModelViewSet` để viết view class cho môn học. Tiếp tục sửa tệp `polls/views.py`, bỏ lớp `SubjectView`, thêm vào lớp có tên là `SubjectViewSet`, mã nguồn như sau:

```Python
from rest_framework.viewsets import ModelViewSet


class SubjectViewSet(ModelViewSet):
    queryset = Subject.objects.all()
    serializer_class = SubjectSerializer
```

Qua việc xem mã nguồn của lớp `ModelViewSet`, ta thấy lớp này có tổng cộng 6 lớp cha, trong đó 5 lớp cha đầu tiên lần lượt hỗ trợ các thao tác POST (thêm mới môn học), GET (lấy môn học chỉ định), PUT/PATCH (cập nhật môn học), DELETE (xóa môn học) và GET (lấy danh sách môn học), tương ứng với các phương thức `create`, `retrieve`, `update`, `destroy` và `list`. Do các lớp cha của `ModelViewSet` đã triển khai sẵn các phương thức này, nên chúng ta gần như không cần viết bất kỳ dòng mã nào cũng hoàn thành xong trọn bộ API cho dữ liệu môn học. Việc duy nhất cần làm là chỉ rõ cách lấy dữ liệu (thông qua thuộc tính `queryset`) và cách tuần tự hóa dữ liệu (thông qua thuộc tính `serializer_class`), điều này hoàn toàn nhất quán với cách làm kế thừa lớp con của `APIView` ở trên.

```Python
class ModelViewSet(mixins.CreateModelMixin,
                   mixins.RetrieveModelMixin,
                   mixins.UpdateModelMixin,
                   mixins.DestroyModelMixin,
                   mixins.ListModelMixin,
                   GenericViewSet):
    """
    A viewset that provides default `create()`, `retrieve()`, `update()`,
    `partial_update()`, `destroy()` and `list()` actions.
    """
    pass
```

Để sử dụng `SubjectViewSet` ở trên, cần cấu hình ánh xạ URL trong tệp `urls.py`. Vì `ModelViewSet` tương đương với việc tập hợp nhiều view function, nên khác với cách ánh xạ URL trước đây, trước tiên chúng ta cần tạo một router và thông qua nó để đăng ký `SubjectViewSet`, sau đó gộp toàn bộ các URL được tạo ra sau khi đăng ký thành công vào danh sách `urlpatterns`, đoạn mã như sau:

```Python
from rest_framework.routers import DefaultRouter

router = DefaultRouter()
router.register('api/subjects', SubjectViewSet)
urlpatterns += router.urls
```

Ngoài lớp `ModelViewSet`, DRF còn cung cấp một lớp có tên là `ReadOnlyModelViewSet`. Nhìn vào tên gọi là có thể thấy, lớp này là tập hợp các view chỉ đọc, đồng nghĩa với việc API tùy biến kế thừa lớp này chỉ hỗ trợ yêu cầu GET, tức là yêu cầu lấy tài nguyên đơn lẻ và danh sách tài nguyên.

### Phân trang dữ liệu

Khi sử dụng yêu cầu GET để lấy danh sách tài nguyên, thông thường chúng ta sẽ không tải toàn bộ dữ liệu trong một lần, trừ khi lượng dữ liệu thực sự rất nhỏ. Hầu hết các thao tác lấy danh sách tài nguyên đều hỗ trợ hiển thị phân trang, nghĩa là chúng ta có thể chỉ định số trang (hoặc định danh tương tự như số trang) và kích thước trang (tải bao nhiêu bản ghi một lần) để lấy dữ liệu khác nhau. Chúng ta có thể thực hiện phân trang thông qua thao tác cắt lát (slicing) trên đối tượng `QuerySet`, hoặc sử dụng các đối tượng `Paginator` và `Page` do Django framework đóng gói sẵn. Khi sử dụng DRF, có thể sửa `REST_FRAMEWORK` trong tệp cấu hình của Django và thiết lập lớp phân trang mặc định cũng như kích thước trang để thực hiện phân trang, như sau:

```Python
REST_FRAMEWORK = {
    'PAGE_SIZE': 10,
    'DEFAULT_PAGINATION_CLASS': 'rest_framework.pagination.PageNumberPagination'
}
```

Ngoài bộ phân trang `PageNumberPagination` được cấu hình ở trên, DRF còn cung cấp các bộ phân trang `LimitOffsetPagination` và `CursorPagination`. Đáng chú ý là `CursorPagination`, nó có thể tránh việc để lộ tổng quy mô dữ liệu của trang web khi phân trang theo số trang thông thường, bạn đọc quan tâm có thể tự tìm hiểu thêm. Nếu không muốn sử dụng cấu hình phân trang mặc định trong tệp cấu hình, bạn có thể thêm thuộc tính `pagination_class` vào view class để chỉ định lại bộ phân trang, thông thường có thể gán thuộc tính này cho một bộ phân trang tự định nghĩa như sau:

```Python
from rest_framework.pagination import PageNumberPagination


class CustomizedPagination(PageNumberPagination):
    # Kích thước trang mặc định
    page_size = 5
    # Tham số truy vấn tương ứng với kích thước trang
    page_size_query_param = 'size'
    # Kích thước trang tối đa
    max_page_size = 50
```

```Python
class SubjectView(ListAPIView):
    # Chỉ định cách lấy dữ liệu
    queryset = Subject.objects.all()
    # Chỉ định cách tuần tự hóa dữ liệu
    serializer_class = SubjectSerializer
    # Chỉ định cách phân trang
    pagination_class = CustomizedPagination
```

Nếu không muốn phân trang dữ liệu, có thể đặt thuộc tính `pagination_class` thành `None` để hủy bộ phân trang mặc định.

### Lọc dữ liệu

Nếu muốn sử dụng CBV để tùy biến API lấy thông tin giảng viên, cũng có thể thực hiện thông qua việc kế thừa `ListAPIView`. Tuy nhiên, vì cần lấy thông tin giảng viên tương ứng theo môn học được chỉ định, nên cần phải lọc dữ liệu giảng viên thay vì lấy toàn bộ dữ liệu giảng viên. Nếu muốn lấy mã môn học từ request và lọc giảng viên theo mã môn học đó, có thể làm được bằng cách ghi đè phương thức `get_queryset`, đoạn mã như sau:

```Python
class TeacherView(ListAPIView):
    serializer_class = TeacherSerializer

    def get_queryset(self):
        queryset = Teacher.objects.defer('subject')
        try:
            sno = self.request.GET.get('sno', '')
            queryset = queryset.filter(subject__no=sno)
            return queryset
        except ValueError:
            raise Http404('No teachers found.')
```

Ngoài cách trên, bạn cũng có thể sử dụng thư viện bên thứ ba `django-filter` kết hợp với DRF để thực hiện lọc dữ liệu. Sau khi sử dụng `django-filter`, có thể cấu hình thuộc tính `filter_backends` cho view class và chỉ định sử dụng `DjangoFilterBackend` để hỗ trợ lọc dữ liệu. Sau khi hoàn tất cấu hình nói trên, có thể dùng thuộc tính `filter_fields` hoặc `filterset_class` để chỉ định cách lọc dữ liệu, bạn đọc quan tâm có thể tự mình tìm hiểu thêm.
