## Chi tiết về SQL: DDL

Thông thường chúng ta có thể chia SQL thành bốn loại, lần lượt là DDL (Data Definition Language - Ngôn ngữ định nghĩa dữ liệu), DML (Data Manipulation Language - Ngôn ngữ thao tác dữ liệu), DCL (Data Control Language - Ngôn ngữ điều khiển dữ liệu) và TCL (Transaction Control Language - Ngôn ngữ điều khiển giao dịch). DDL chủ yếu được dùng để tạo, xóa, sửa đổi các đối tượng trong cơ sở dữ liệu, chẳng hạn như tạo, xóa và sửa đổi bảng hai chiều, các từ khóa cốt lõi bao gồm `create`, `drop` và `alter`; DML chủ yếu chịu trách nhiệm chèn, xóa, cập nhật và truy vấn dữ liệu, các từ khóa bao gồm `insert`, `delete`, `update` và `select`; DCL dùng để cấp và thu hồi quyền hạn, các từ khóa cốt lõi là `grant` và `revoke`; TCL thường dùng để kiểm soát giao dịch.

> **Giải thích**: SQL là ngôn ngữ không phân biệt chữ hoa chữ thường. Thông thường chúng tôi khuyên bạn nên viết hoa các từ khóa và viết thường các phần còn lại. Nếu quy chuẩn lập trình SQL của công ty có quy định bắt buộc thì hãy tuân theo yêu cầu của công ty; sở thích cá nhân không nên đặt trên quy chuẩn lập trình của tập thể, đây là điều hiển nhiên đối với người làm việc chuyên nghiệp.

### Tạo cơ sở dữ liệu và tạo bảng

Dưới đây, chúng ta sẽ xây dựng cơ sở dữ liệu cho một hệ thống chọn môn học (đăng ký học phần) của trường học rất đơn giản. Chúng ta đặt tên cơ sở dữ liệu là `school`. Bốn thực thể quan trọng lần lượt là khoa (học viện), giảng viên, sinh viên và môn học. Trong đó, sinh viên và khoa có mối quan hệ trực thuộc; xét về mặt số lượng thì đây là quan hệ nhiều-một, vì một khoa có thể có nhiều sinh viên, còn một sinh viên thông thường chỉ thuộc về một khoa; tương tự, mối quan hệ trực thuộc giữa giảng viên và khoa cũng là quan hệ nhiều-một. Một giảng viên có thể giảng dạy nhiều môn học, nếu một môn học chỉ do một giảng viên phụ trách thì môn học và giảng viên cũng là quan hệ nhiều-một; nếu cho phép nhiều giảng viên cùng hợp tác giảng dạy một môn học thì môn học và giảng viên là quan hệ nhiều-nhiều. Để đơn giản, chúng ta thiết kế môn học và giảng viên theo quan hệ nhiều-một. Sinh viên và môn học là quan hệ nhiều-nhiều điển hình, vì một sinh viên có thể đăng ký nhiều môn học, và một môn học cũng có thể được nhiều sinh viên lựa chọn. Cơ sở dữ liệu quan hệ cần nhờ đến bảng trung gian để duy trì mối quan hệ nhiều-nhiều giữa hai thực thể. Cuối cùng, hệ thống chọn môn học của trường chúng ta có tổng cộng năm bảng, lần lượt là bảng khoa (`tb_college`), bảng sinh viên (`tb_student`), bảng giảng viên (`tb_teacher`), bảng môn học (`tb_course`) và bảng ghi nhận chọn môn (`tb_record`). Trong đó, bảng ghi nhận chọn môn chính là bảng trung gian duy trì mối quan hệ nhiều-nhiều giữa sinh viên và môn học.

```SQL
-- Nếu tồn tại cơ sở dữ liệu tên là school thì xóa đi
DROP DATABASE IF EXISTS `school`;

-- Tạo cơ sở dữ liệu tên là school và thiết lập bộ ký tự cùng quy tắc sắp xếp mặc định
CREATE DATABASE `school` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

-- Chuyển sang ngữ cảnh cơ sở dữ liệu school
USE `school`;

-- Tạo bảng khoa
CREATE TABLE `tb_college`
(
`col_id`    int unsigned AUTO_INCREMENT      COMMENT 'Mã khoa',
`col_name`  varchar(50)  NOT NULL            COMMENT 'Tên khoa',
`col_intro` varchar(500) NOT NULL DEFAULT '' COMMENT 'Giới thiệu',
PRIMARY KEY (`col_id`)
);

-- Tạo bảng sinh viên
CREATE TABLE `tb_student`
(
`stu_id`    int unsigned NOT NULL           COMMENT 'Mã sinh viên',
`stu_name`  varchar(20)  NOT NULL           COMMENT 'Họ và tên',
`stu_sex`   boolean      NOT NULL DEFAULT 1 COMMENT 'Giới tính',
`stu_birth` date         NOT NULL           COMMENT 'Ngày sinh',
`stu_addr`  varchar(255) DEFAULT ''         COMMENT 'Quê quán',
`col_id`    int unsigned NOT NULL           COMMENT 'Khoa trực thuộc',
PRIMARY KEY (`stu_id`),
CONSTRAINT `fk_student_col_id` FOREIGN KEY (`col_id`) REFERENCES `tb_college` (`col_id`)
);

-- Tạo bảng giảng viên
CREATE TABLE `tb_teacher`
(
`tea_id`    int unsigned NOT NULL                COMMENT 'Mã giảng viên',
`tea_name`  varchar(20)  NOT NULL                COMMENT 'Họ và tên',
`tea_title` varchar(10)  NOT NULL DEFAULT '助教' COMMENT 'Chức danh',
`col_id`    int unsigned NOT NULL                COMMENT 'Khoa trực thuộc',
PRIMARY KEY (`tea_id`),
CONSTRAINT `fk_teacher_col_id` FOREIGN KEY (`col_id`) REFERENCES `tb_college` (`col_id`)
);

-- Tạo bảng môn học
CREATE TABLE `tb_course`
(
`cou_id`     int unsigned NOT NULL COMMENT 'Mã môn học',
`cou_name`   varchar(50)  NOT NULL COMMENT 'Tên môn học',
`cou_credit` int          NOT NULL COMMENT 'Số tín chỉ',
`tea_id`     int unsigned NOT NULL COMMENT 'Giảng viên phụ trách',
PRIMARY KEY (`cou_id`),
CONSTRAINT `fk_course_tea_id` FOREIGN KEY (`tea_id`) REFERENCES `tb_teacher` (`tea_id`)
);

-- Tạo bảng ghi nhận chọn môn
CREATE TABLE `tb_record`
(
`rec_id`   bigint unsigned AUTO_INCREMENT COMMENT 'Mã bản ghi',
`stu_id`   int unsigned    NOT NULL       COMMENT 'Mã sinh viên',
`cou_id`   int unsigned    NOT NULL       COMMENT 'Mã môn học',
`sel_date` date            NOT NULL       COMMENT 'Ngày chọn môn',
`score`    decimal(4,1)                   COMMENT 'Điểm thi',
PRIMARY KEY (`rec_id`),
CONSTRAINT `fk_record_stu_id` FOREIGN KEY (`stu_id`) REFERENCES `tb_student` (`stu_id`),
CONSTRAINT `fk_record_cou_id` FOREIGN KEY (`cou_id`) REFERENCES `tb_course` (`cou_id`),
CONSTRAINT `uk_record_stu_cou` UNIQUE (`stu_id`, `cou_id`)
);
```

Có một vài điểm trong đoạn DDL trên cần được nhấn mạnh:

- Trước hết, tên cơ sở dữ liệu, tên bảng và tên trường (cột) trong đoạn SQL trên đều được bao quanh bởi dấu backtick (\`). Dấu backtick không bắt buộc, nhưng lại có thể giải quyết vấn đề xung đột giữa tên bảng, tên trường với các từ khóa SQL (các từ có ý nghĩa đặc biệt trong SQL).

- Khi tạo cơ sở dữ liệu, chúng ta thông qua `default character set utf8mb4` để chỉ định bộ ký tự mặc định của cơ sở dữ liệu là `utf8mb4` (mã hóa `utf-8` tối đa `4` byte). - Khi tạo và xóa cơ sở dữ liệu, từ khóa `database` cũng có thể thay thế bằng `schema`, cả hai có tác dụng như nhau.

- Trong câu lệnh tạo bảng, `not null` là ràng buộc không rỗng, giới hạn trường dữ liệu không được phép để trống; `default` dùng để chỉ định giá trị mặc định cho trường, chúng ta gọi là ràng buộc giá trị mặc định; `primary key` là ràng buộc khóa chính, quy định cột có thể xác định duy nhất một bản ghi và đảm bảo mỗi bản ghi là duy nhất vì khóa chính không cho phép trùng lặp; `foreign key` là ràng buộc khóa ngoại, duy trì tính toàn vẹn tham chiếu giữa hai bảng. Lấy ví dụ, do trong bảng sinh viên chúng ta thêm ràng buộc khóa ngoại cho trường col_id, quy định nó phải tham chiếu (`references`) đến col_id trong bảng khoa, do đó mã khoa trong bảng sinh viên bắt buộc phải xuất phát từ mã khoa trong bảng khoa, không thể gán giá trị tùy tiện cho trường này. Nếu cần đặt tên cho ràng buộc khóa chính, ràng buộc khóa ngoại, v.v., bạn có thể sử dụng từ khóa `constraint` kèm theo tên ràng buộc phía sau.

- Từ khóa `comment` trong câu lệnh tạo bảng được dùng để thêm chú thích cho cột và bảng, nâng cao tính dễ đọc và dễ bảo trì của mã nguồn.

- Khi tạo bảng, bạn có thể tự mình lựa chọn storage engine (công cụ lưu trữ) bên dưới. MySQL hỗ trợ nhiều storage engine khác nhau, bạn có thể xem bằng lệnh `show engines`. Kể từ phiên bản MySQL 5.5 trở đi, engine mặc định là InnoDB, và đây cũng là storage engine mà chúng tôi khuyên bạn nên sử dụng (vì nó phù hợp hơn với nhu cầu của các ứng dụng Internet hiện nay về tính đồng thời cao, hiệu năng cũng như hỗ trợ giao dịch). Để đảm bảo tính tương thích ngược của câu lệnh SQL, chúng ta có thể chỉ định sử dụng engine InnoDB bằng cách viết `engine=innodb` ở phía sau dấu ngoặc đơn đóng của câu lệnh tạo bảng.

  ```
  VARCHAR is shorthand for CHARACTER VARYING. NATIONAL VARCHAR is the
  standard SQL way to define that a VARCHAR column should use some
  predefined character set. MySQL uses utf8 as this predefined character
  set. http://dev.mysql.com/doc/refman/5.7/en/charset-national.html.
  NVARCHAR is shorthand for NATIONAL VARCHAR.
  
  URL: http://dev.mysql.com/doc/refman/5.7/en/string-type-overview.html
  ```
  
  Về việc lựa chọn kiểu dữ liệu, khi lưu trữ dữ liệu chuỗi thường sử dụng hai kiểu là VARCHAR và CHAR, trong đó kiểu trước thường được gọi là chuỗi có độ dài thay đổi (biến dài), còn kiểu sau là chuỗi có độ dài cố định (định dài); đối với storage engine InnoDB, định dạng lưu trữ theo dòng không phân biệt cột có độ dài cố định hay độ dài thay đổi, do đó kiểu VARCHAR và CHAR không có sự khác biệt về bản chất, kiểu sau chưa chắc đã có hiệu năng tốt hơn kiểu trước. Nếu muốn lưu trữ chuỗi văn bản rất lớn, bạn có thể sử dụng kiểu TEXT; nếu muốn lưu trữ chuỗi byte rất lớn, có thể dùng kiểu BLOB (Binary Large Object - Đối tượng nhị phân lớn). Trong MySQL, TEXT và BLOB lần lượt bao gồm ba kiểu khác nhau là TEXT, MEDIUMTEXT, LONGTEXT và BLOB, MEDIUMBLOB, LONGBLOB; điểm khác biệt chủ yếu giữa chúng nằm ở kích thước tối đa của dữ liệu lưu trữ. Để lưu trữ số thực dấu phẩy động có thể dùng kiểu FLOAT hoặc DOUBLE; FLOAT hiện không còn được khuyến khích sử dụng và có thể sẽ bị loại bỏ trong các phiên bản MySQL tương lai. Còn khi lưu trữ số dấu phẩy tĩnh (số có độ chính xác cố định) thì nên sử dụng kiểu DECIMAL, nó cho phép chỉ định số chữ số có nghĩa trước và sau dấu thập phân. Nếu cần lưu trữ thời gian và ngày tháng, kiểu DATETIME tốt hơn kiểu TIMESTAMP vì khoảng thời gian ngày tháng mà DATETIME biểu diễn rộng hơn nhiều; kiểu TIMESTAMP bên dưới thực chất là một số nguyên ghi lại số giây chênh lệch giữa ngày giờ được chỉ định so với 1970-01-01 00:00:00, và kiểu này sẽ bị tràn số sau 03:14:07 ngày 19-01-2038.
  
  Đối với trường tự tăng AUTO_INCREMENT, nếu bạn dùng phiên bản MySQL 5.x thì cần lưu ý vấn đề hồi quy (tái sử dụng giá trị ID sau khi restart) của trường tự tăng; tất nhiên vấn đề này đã được giải quyết triệt để trong MySQL 8.x. Ngoài ra MySQL 8.x còn có rất nhiều điểm ưu việt khác với nhiều tối ưu hóa và điều chỉnh cả về tính năng lẫn hiệu năng, vì vậy chúng tôi thực sự khuyên bạn nên sử dụng phiên bản MySQL 8.x. Đối với các kịch bản truy cập cơ sở dữ liệu có tính đồng thời cao, AUTO_INCREMENT không chỉ gặp vấn đề về hiệu năng mà còn có thể tạo ra các giá trị ID trùng lặp trên kiến trúc nhiều máy; trong các kịch bản như vậy, việc sử dụng thuật toán tạo ID phân tán (SnowFlake, TinyID, v.v.) mới là sự lựa chọn tốt nhất, độc giả quan tâm có thể tự mình tìm hiểu thêm.

### Xóa bảng và sửa đổi bảng

Dưới đây, chúng ta lấy bảng sinh viên làm ví dụ để giải thích cách xóa bảng và sửa đổi bảng. Để xóa bảng, bạn có thể dùng `drop table`, đoạn mã như sau:

```SQL
DROP TABLE `tb_student`;
```

hoặc

```SQL
DROP TABLE IF EXISTS `tb_student`;
```

Cần lưu ý rằng, nếu bảng sinh viên đã được nhập dữ liệu và dữ liệu đó đang được bảng khác tham chiếu đến thì bạn không thể xóa bảng sinh viên, nếu không thao tác trên sẽ báo lỗi. Trong bài học tiếp theo, chúng ta sẽ tìm hiểu cách chèn dữ liệu vào bảng, lúc đó các bạn có thể thử xem liệu có thể xóa bảng sinh viên một cách thuận lợi hay không.

Nếu muốn sửa đổi bảng sinh viên, bạn có thể sử dụng `alter table`, cụ thể có thể chia thành các trường hợp sau:

Sửa bảng, thêm một cột mới, ví dụ thêm cột số điện thoại liên hệ vào bảng sinh viên:

```SQL
ALTER TABLE `tb_student` ADD COLUMN `stu_tel` varchar(20) NOT NULL COMMENT 'Số điện thoại liên hệ';
```

> **Lưu ý**: Khi thêm cột mới, nếu chỉ định ràng buộc không rỗng (`not null`) thì bảng sinh viên không được có dữ liệu, nếu không dữ liệu cũ sau khi thêm cột stu_tel sẽ không có dữ liệu cho cột này, dẫn đến vi phạm yêu cầu của ràng buộc không rỗng; tất nhiên, khi thêm cột chúng ta cũng có thể sử dụng ràng buộc giá trị mặc định để giải quyết vấn đề này.

Sửa bảng, xóa một cột được chỉ định, ví dụ xóa cột số điện thoại liên hệ vừa thêm ở trên:

```SQL
ALTER TABLE `tb_student` DROP COLUMN `stu_tel`;
```

Sửa bảng, thay đổi kiểu dữ liệu của cột, ví dụ đổi stu_sex trong bảng sinh viên thành kiểu ký tự:

```SQL
ALTER TABLE `tb_student` MODIFY COLUMN `stu_sex` char(1) NOT NULL DEFAULT 'M' COMMENT 'Giới tính';
```

Sửa bảng, đổi tên cột, ví dụ đổi stu_sex trong bảng sinh viên thành stu_gender:

```SQL
ALTER TABLE `tb_student` CHANGE COLUMN `stu_sex` `stu_gender` boolean DEFAULT 1 COMMENT 'Giới tính';
```

Sửa bảng, xóa điều kiện ràng buộc, ví dụ xóa ràng buộc khóa ngoại trên cột col_id của bảng sinh viên:

```SQL
ALTER TABLE `tb_student` DROP FOREIGN KEY `fk_student_col_id`;
```

Sửa bảng, thêm điều kiện ràng buộc, ví dụ thêm ràng buộc khóa ngoại cho cột col_id của bảng sinh viên:

```SQL
ALTER TABLE `tb_student` ADD FOREIGN KEY (`col_id`) REFERENCES `tb_college` (`col_id`);
```

hoặc

```SQL
ALTER TABLE `tb_student` ADD CONSTRAINT `fk_student_col_id` FOREIGN KEY (`col_id`) REFERENCES `tb_college` (`col_id`);
```

> **Giải thích**: Khi thêm ràng buộc khóa ngoại, bạn còn có thể thông qua `on update` và `on delete` để chỉ định cách xử lý tương ứng khi bảng được tham chiếu xảy ra thao tác xóa và cập nhật. Giá trị mặc định của cả hai đều là `restrict`, nghĩa là nếu tồn tại ràng buộc khóa ngoại thì không cho phép cập nhật hoặc xóa dữ liệu đang được tham chiếu. Ngoài `restrict` ra, các giá trị có thể chọn ở đây còn có `cascade` (thao tác theo tầng / liên hoàn) và `set null` (thiết lập thành NULL), độc giả quan tâm có thể tự mình tìm hiểu thêm.

Sửa tên bảng, ví dụ đổi tên bảng sinh viên thành tb_stu_info:

```SQL
ALTER TABLE `tb_student` RENAME TO `tb_stu_info`;
```

> **Gợi ý**: Thông thường, xin vui lòng không tùy tiện thay đổi tên cơ sở dữ liệu hoặc tên bảng.
