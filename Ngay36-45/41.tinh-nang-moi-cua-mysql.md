## Các tính năng mới của MySQL

### Kiểu dữ liệu JSON

Nhiều nhà phát triển khi sử dụng cơ sở dữ liệu quan hệ để lưu trữ dữ liệu bền vững (persistence) thường cảm thấy việc lưu trữ có cấu trúc bị thiếu tính linh hoạt, bởi vì bắt buộc phải thiết kế trước tất cả các cột cũng như các kiểu dữ liệu tương ứng. Trong quá trình phát triển và thay đổi của nghiệp vụ, nếu cần sửa đổi cấu trúc bảng thì đây chắc chắn là một điều tương đối phiền toái và khó chịu. Bắt đầu từ phiên bản MySQL 5.7, MySQL đã đưa vào hỗ trợ kiểu dữ liệu JSON (MySQL 8.0 đã giải quyết vấn đề nghẽn cổ chai hiệu năng ghi log của JSON). Tận dụng tốt kiểu JSON thực chất là phá vỡ ranh giới giữa cơ sở dữ liệu quan hệ và cơ sở dữ liệu phi quan hệ (NoSQL), mang lại nhiều sự thuận tiện hơn cho các thao tác lưu trữ dữ liệu bền vững.

Kiểu JSON chủ yếu được chia thành hai dạng là JSON object (đối tượng JSON) và JSON array (mảng JSON), như dưới đây:

1. Đối tượng JSON

```JSON
{"name": "jackfrued", "tel": "13122335566", "QQ": "957658"}
```

2. Mảng JSON

```JSON
[1, 2, 3]
```

```JSON
[{"name": "jackfrued", "tel": "13122335566"}, {"name": "Vương Đại Chùy", "QQ": "123456"}]
```

Những trường hợp nào cần sử dụng kiểu JSON? Lấy một ví dụ đơn giản: hiện nay nhiều sản phẩm hỗ trợ đăng nhập người dùng bằng nhiều phương thức khác nhau, ví dụ như số điện thoại di động, WeChat, QQ, Sina Weibo, v.v., nhưng thông thường chúng ta lại không bắt buộc người dùng phải cung cấp tất cả các thông tin này. Với cách thiết kế truyền thống, chúng ta sẽ phải thiết kế nhiều cột tương ứng với nhiều phương thức đăng nhập và có thể cần cho phép các cột này chứa giá trị null; đây rõ ràng không phải là một lựa chọn tối ưu. Mặt khác, nếu sản phẩm bổ sung thêm một phương thức đăng nhập mới thì chắc chắn chúng ta phải sửa lại cấu trúc bảng trước đó, điều này lại càng gây phiền toái. Tuy nhiên, khi đã có kiểu JSON thì vấn đề trên được giải quyết một cách dễ dàng, chúng ta có thể thiết kế như sau:

```SQL
CREATE TABLE `tb_test`
(
`user_id`    bigint unsigned,
`login_info` json,
PRIMARY KEY (`user_id`)
);

INSERT INTO `tb_test` 
VALUES 
    (1, '{"tel": "13122335566", "QQ": "654321", "wechat": "jackfrued"}'),
    (2, '{"tel": "13599876543", "weibo": "wangdachui123"}');
```

Nếu muốn truy vấn số điện thoại và tài khoản WeChat của người dùng, có thể dùng câu lệnh SQL như sau:

```SQL
SELECT `user_id`
     , JSON_UNQUOTE(JSON_EXTRACT(`login_info`, '$.tel')) AS `so_dien_thoai`
     , JSON_UNQUOTE(JSON_EXTRACT(`login_info`, '$.wechat')) AS `wechat` 
FROM `tb_test`;
```

```
+---------+---------------+-----------+
| user_id | so_dien_thoai | wechat    |
+---------+---------------+-----------+
|       1 | 13122335566   | jackfrued |
|       2 | 13599876543   | NULL      |
+---------+---------------+-----------+
```

Vì hỗ trợ kiểu JSON, MySQL cũng cung cấp bộ hàm tương ứng để xử lý dữ liệu JSON, giống như `json_extract` và `json_unquote` được dùng ở trên. Tất nhiên, câu lệnh SQL trên còn có cách viết ngắn gọn và tiện lợi hơn như sau:

```SQL
SELECT `user_id`
     , `login_info` ->> '$.tel' AS `so_dien_thoai`
     , `login_info` ->> '$.wechat' AS `wechat`
  FROM `tb_test`;
```

Lấy thêm một ví dụ nữa, nếu sản phẩm của chúng ta cần thực hiện tính năng hồ sơ người dùng (gắn thẻ / gắn tag cho người dùng), rồi dựa trên hồ sơ người dùng để đề xuất các dịch vụ hoặc sản phẩm tiêu dùng trên nền tảng, chúng ta cũng có thể sử dụng kiểu JSON để lưu trữ dữ liệu hồ sơ người dùng, mã lệnh minh họa như sau:

Tạo bảng nhãn hồ sơ:

```SQL
CREATE TABLE `tb_tags`
(
`tag_id`   int unsigned NOT NULL COMMENT 'Mã nhãn',
`tag_name` varchar(20)  NOT NULL COMMENT 'Tên nhãn',
PRIMARY KEY (`tag_id`)
);

INSERT INTO `tb_tags` (`tag_id`, `tag_name`) 
VALUES
    (1, '70后'),
    (2, '80后'),
    (3, '90后'),
    (4, '00后'),
    (5, '爱运动'),
    (6, '高学历'),
    (7, '小资'),
    (8, '有房'),
    (9, '有车'),
    (10, '爱看电影'),
    (11, '爱网购'),
    (12, '常点外卖');
```

Gắn nhãn cho người dùng:

```SQL
CREATE TABLE `tb_users_tags`
(
`user_id`   bigint unsigned NOT NULL COMMENT 'Mã người dùng',
`user_tags` json            NOT NULL COMMENT 'Nhãn người dùng'
);

INSERT INTO `tb_users_tags`
VALUES
    (1, '[2, 6, 8, 10]'),
    (2, '[3, 10, 12]'),
    (3, '[3, 8, 9, 11]');
```

Tiếp theo, chúng ta thông qua một nhóm truy vấn để thấy được sự khéo léo và tiện lợi của kiểu JSON:

1. Truy vấn ID người dùng thích xem phim (có nhãn `10`):

    ```SQL
    SELECT `user_id`
      FROM `tb_users_tags`
     WHERE 10 MEMBER OF (`user_tags`->'$');
    ```

2. Truy vấn ID người dùng thế hệ 8x (có nhãn `2`) thích xem phim (có nhãn `10`):

    ```SQL
    SELECT `user_id`
      FROM `tb_users_tags`
     WHERE JSON_CONTAINS(`user_tags`->'$', '[2, 10]');
    ```

3. Truy vấn ID người dùng thích xem phim, hoặc thế hệ 8x, hoặc thế hệ 9x:

    ```SQL
    SELECT `user_id`
      FROM `tb_users_tags`
     WHERE JSON_OVERLAPS(user_tags->'$', '[2, 3, 10]');
    ```

> **Giải thích**: Các câu truy vấn trên đã sử dụng vị từ `member of` và hai hàm xử lý JSON: `json_contains` dùng để kiểm tra xem mảng JSON có chứa các phần tử được chỉ định hay không, còn `json_overlaps` dùng để kiểm tra xem mảng JSON có phần tử trùng lặp (giao nhau) với mảng được chỉ định hay không.

### Hàm cửa sổ

MySQL bắt đầu hỗ trợ hàm cửa sổ (window function) từ phiên bản 8.0. Đa số các cơ sở dữ liệu thương mại và một số cơ sở dữ liệu nguồn mở đã cung cấp hỗ trợ cho hàm cửa sổ từ rất sớm; một số nơi còn gọi chúng là các hàm OLAP (Online Analytical Processing - Xử lý phân tích trực tuyến), nghe tên là biết chúng liên quan đến thống kê và phân tích dữ liệu. Để giúp các bạn hiểu rõ hàm cửa sổ, trước tiên chúng ta nói về khái niệm "cửa sổ" (window).

Cửa sổ có thể hiểu là một tập hợp các bản ghi, hàm cửa sổ chính là hàm đặc biệt được thực thi trên tập hợp các bản ghi thỏa mãn điều kiện nhất định, và đối với mỗi bản ghi thì hàm đều được thực thi trong phạm vi cửa sổ này. Hàm cửa sổ và các hàm tổng hợp (aggregate function) mà chúng ta đã tìm hiểu ở trên rất dễ bị nhầm lẫn; điểm khác biệt chủ yếu giữa hai loại là hàm tổng hợp sẽ gộp nhiều bản ghi thành một bản ghi duy nhất, còn hàm cửa sổ thì mỗi bản ghi đều sẽ được thực thi và sau khi thực thi thì số lượng bản ghi không hề thay đổi. Hàm cửa sổ không chỉ là một vài hàm đơn lẻ, mà nó là một bộ cú pháp hoàn chỉnh, bản thân hàm chỉ là một phần trong cú pháp đó. Cú pháp cơ bản như sau:

```SQL
<hàm cửa sổ> OVER (PARTITION BY <tên cột dùng để gom nhóm> ORDER BY <tên cột dùng để sắp xếp> ROWS BETWEEN ... AND ...)
<hàm cửa sổ> OVER (PARTITION BY <tên cột dùng để gom nhóm> ORDER BY <tên cột dùng để sắp xếp> RANGE BETWEEN ... AND ...)
```

Trong cú pháp trên, vị trí của hàm cửa sổ có thể đặt hai loại hàm sau:

1. Hàm cửa sổ chuyên dụng, bao gồm: `lead`, `lag`, `first_value`, `last_value`, `rank`, `dense_rank`, `row_number`, v.v.
2. Hàm tổng hợp, bao gồm: `sum`, `avg`, `max`, `min`, `count`, v.v.

Dưới đây là một vài ví dụ đơn giản về việc sử dụng hàm cửa sổ, chúng ta trực tiếp sử dụng cơ sở dữ liệu `hrs` đã tạo ở các bài trước.

Ví dụ 1: Truy vấn họ tên và lương tháng của những nhân viên xếp thứ 4 đến thứ 6 theo mức lương tháng từ cao xuống thấp:

```SQL
SELECT * 
  FROM (SELECT `ename`
             , `sal`
             , ROW_NUMBER() over (ORDER BY `sal` DESC) AS `rk`
	      FROM `tb_emp`) AS `temp`
 WHERE `rk` between 4 and 6;
```

> **Giải thích**: Hàm `row_number()` được sử dụng ở trên có thể tạo số thứ tự dòng cho mỗi bản ghi. Trong công việc thực tế, bạn có thể thay thế bằng hàm `rank()` hoặc `dense_rank()` tùy theo nhu cầu. Sự khác biệt giữa ba hàm này có thể tham khảo trong tài liệu chính thức hoặc đọc bài viết [《Dễ hiểu, dễ học: Hàm cửa sổ trong SQL》](https://zhuanlan.zhihu.com/p/92654574) để tìm hiểu thêm. Ở các phiên bản trước MySQL 8, chúng ta có thể thực hiện thao tác tương tự theo cách sau:
>
> ```SQL
> select `rank`, `ename`, `sal` from (
>        select @a:=@a+1 as `rank`, `ename`, `sal` 
>        from `tb_emp`, (select @a:=0) as t1 order by `sal` desc
> ) as `temp` where `rank` between 4 and 6;
> ```

Ví dụ 2: Truy vấn họ tên nhân viên và tên phòng ban của hai nhân viên có lương tháng cao nhất trong mỗi phòng ban:

```SQL
select `ename`, `sal`, `dname` 
from (
    select 
        `ename`, `sal`, `dno`,
        rank() over (partition by `dno` order by `sal` desc) as `rank`
    from `tb_emp`
) as `temp` natural join `tb_dept` where `rank`<=2;
```

> **Giải thích**: Ở các phiên bản trước MySQL 8, chúng ta có thể thực hiện thao tác tương tự theo cách sau:
>
> ```SQL
> select `ename`, `sal`, `dname` from `tb_emp` as `t1` 
> natural join `tb_dept` 
> where (
>         select count(*) from `tb_emp` as `t2` 
>         where `t1`.`dno`=`t2`.`dno` and `t2`.`sal`>`t1`.`sal` 
> )<2 order by `dno` asc, `sal` desc;
> ```
